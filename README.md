# 레드문 JS (시험판)

레드문을 브라우저에서 돌아가는 온라인 게임으로 옮기는 프로젝트입니다.
지금 단계는 **전체 맵(253장)을 오가며 여러 명이 이동·채팅하고, 몬스터와 싸워 경험치와 아이템을 얻는 것**까지입니다.

## 실행

Node.js 18 이상이 필요합니다.

```
npm install
npm start
```

브라우저에서 http://localhost:3000 을 열고 이름을 넣으면 접속됩니다.
창을 여러 개 열면 서로 보입니다. 포트는 `PORT=8080 npm start` 처럼 바꿀 수 있습니다.

| 조작 | 동작 |
|---|---|
| 클릭(누르고 있으면 계속) | 이동 |
| 몬스터 클릭 | 다가가서 공격 |
| 바닥 아이템 클릭 | 걸어가서 줍기 |
| I | 소지품 창 (아이템 클릭: 사용·착용, 착용 칸 클릭: 벗기) |
| NPC 클릭 | 다가가서 말 걸기 (연결된 이벤트 실행) |
| Shift+클릭 또는 R | 달리기 |
| Enter | 채팅 |
| + / − | 확대 / 축소 |
| 채팅창에 `/맵 3` | 그 번호의 맵으로 바로 이동 (시험용) |
| 채팅창에 `/아이템 1 3 [수량]` | 분류 1의 3번 아이템 받기 (시험용) |
| 채팅창에 `/돈 100000` | 돈 받기 (시험용) |

## 자료 변환 (그림·소리·서버 자료 전부)

```
node --max-old-space-size=4096 tools/convert.js "C:\RMA\Redmoon" --all --server "C:\Redmoon3944_Server\Bin\Data"
```

## 구조

```
tools/formats.js   원본 파일 형식 해독 (LST, RMD, RLE, RMM) + PNG 저장
tools/convert.js   클라이언트 자료 → assets/ (PNG, JSON)
server/index.js    웹 서버 + WebSocket
server/formulas.js 원작 서버에서 옮긴 계산식 (체력, 공격력, 명중, 경험치, 능력치)
server/sprites.js  원작 클라이언트에서 옮긴 모습 번호 → 그림 번호 표
server/world.js    게임 규칙: 맵별 세계, 이동, 길찾기, 맵 이동, 몬스터 행동, 전투 진행
public/            브라우저 클라이언트 (화면과 입력만 담당)
assets/            변환된 그림과 맵 자료 (브라우저로 전송됨)
data/              서버만 쓰는 자료: 몬스터 표, 맵별 배치·이벤트·NPC
```

이동은 전부 서버가 판정합니다. 클라이언트는 "여기로 가고 싶다"만 보내고,
서버가 길을 찾아 한 칸씩 움직인 결과를 모두에게 알립니다.

## 해독한 파일 형식

- **RLE** (그림 묶음): `Resource File` 머리말, 그림 수, 위치표. 그림마다 기준점·크기와 RGB565 줄길이 압축 자료.
  명령 1=픽셀 n개, 2=가로 이동(음수 가능), 3=다음 줄, 0=끝.
- **LST** (그림 목록): 그림 id → RLE 파일 번호와 순번.
- **RMD** (스프라이트 정의): 항목마다 여러 겹의 그림(잘라낼 영역, 깊이 기준, 그릴 위치, 섞는 방식, 속성). 뒤에 동작표가 붙음.
  캐릭터 동작표는 `동작번호×10 + 방향`(방향은 숫자 키패드 배열: 2=아래, 8=위).
  확인한 동작: 0=걷기, 1=달리기, 6=서 있기, 2·3=공격.
- **RMM** (맵): 칸(48×24픽셀)마다 8바이트.
  바닥 타일(파일 9비트 + 순번 10비트), 오브젝트 조각(파일 11비트 + 순번), 이동 가능 여부(대타일 면·본타일 면 각 2비트).
  좌표는 서버와 같습니다. 칸(48×24픽셀)마다 서는 자리가 둘 있습니다: 자리 0은 칸의 왼쪽 위 모서리, 자리 1은 칸 한가운데.
  가로·세로 한 걸음은 48·24픽셀, 대각선 한 걸음은 (24, 12)픽셀이고 대각선으로 걸을 때마다 자리가 바뀝니다 (`server/grid.js`).

- **서버 자료** (3.944 기준, 글자표는 EUC-KR 텍스트)
  - `MopInfo.rsm`: 종류, 모습, 시야, 이동속도, 공격범위 1·2, 공격간격 1·2, 총알 1·2, 기술 1·2, 근력·정신력·민첩성·기골, 경험치, 공격 가능 방향 1·2, 명성치, 자리 차지 안 함.
    모습 번호와 클라이언트 그림 번호의 대응은 `server/sprites.js` 의 표를 따릅니다.
  - `Mop000NN.rsm`: 이름, 종류, 배치 영역(타일), 떨어뜨리는 아이템 목록, 마릿수, 리젠 시간(초).
  - `MapNNNNN.smm`: 칸마다 64비트(상위 4바이트 먼저). 비트 30~37 이벤트 번호, 비트 48·56 주인공 이동 가능(자리 0·1), 비트 49·57 몬스터 이동 가능(자리 0·1),
    비트 40~47 그 자리에 누가 서 있는지 (`CrsMap::Serialize`, `GetEvent`, `GetCanExistUser`, `GetCanExistMop`, `Move` 에서 확인).
  - `EventNNNNN.rse`: 이벤트 번호별 종류. 1 = 맵 이동(맵, x, y), 5 = 안전지대.
  - `skill00.rmi`: 기술 191개. 파일 구조(값의 순서와 크기)는 `CrSkillInfo::Serialize` 대로 풀어 `data/skills.json` 에 넣었지만, 값 하나하나의 뜻은 아직 읽지 못했습니다.
  - `EventInfo.rse`: NPC용 공용 이벤트 표. 번호 → 종류(6 은행, 8 의사, 20 거래소, 31~37 상점 …)와 정보.
  - `ShopNNNNN.rss`: 분류, 번호, 수량(4000000001 = 무제한), 가격 비율(%), 표시(1 = 상점이 판다, 2 = 상점이 사 준다).
  - `ExtraNNNNN.rme`: NPC 이름, 모습, 이벤트, 서 있는 영역.
  - `ItemInfo0N.rsi`: 분류별 아이템. 항목마다 분류, 아이콘 번호, 이름, 설명, 수치 74바이트(체력 회복, 마력 회복, 공격, 방어, 요구 수치, 종류, 가격).
    아이콘은 `assets/ico/<분류>` 의 항목 2n(소지품 칸 그림), 2n+1(바닥에 놓인 그림)입니다.

`server/formulas.js` 에 그대로 옮겼습니다. 함수마다 실행 파일 안의 주소를 주석으로 달았습니다.

### 아직 읽지 못한 부분

원본에서 확인하지 못한 채 넣은 것은 아래 세 가지이며, 나머지는 위 표대로 원본에서 확인한 값입니다.

- **주인공의 길찾기.** 원작은 클라이언트가 길을 찾고 서버는 한 걸음씩 검사합니다. 여기서는 서버가 A*로 길을 찾습니다.
- **주인공이 공격을 되풀이하는 박자.** 공격 동작 한 번의 길이(동작표 칸 수 × 50ms)를 간격으로 씁니다. 화면 한 장 50ms 와 동작표를 한 장에 한 칸씩 넘기는 것은
  원본에서 확인했지만, 동작이 끝난 뒤 다음 공격을 보내기까지의 처리는 아직 읽지 못했습니다. 서버는 0.1초 안에 거듭 온 공격만 버립니다(`ProcessUserAttack`).
- **기력이 0일 때 달리기 대신 걷게 한 것**, 강화형 몬스터 조건을 배치표의 패턴 5로 본 것, NPC 자리를 주인공용 이동 가능 비트로 고르는 것.

아직 구현하지 않은 원작 규칙 (읽으면 그대로 옮길 것):

- 몬스터 행동 중 기술과 얽힌 갈래: 기술을 가진 몬스터의 기술 사용(`DoSpecialAction`, `UseSkill`, `UseSkillRange`), 기술에 걸린 상태(혼란·은신·도발)에 따른 분기,
  패턴 2 몬스터가 대상을 처음 볼 때 외치는 말(메시지 153~157번), 패턴 3(이벤트로 표시된 주인공만 공격), 모습 86·87·97·98(군단 기지 경비)의 군단 관련 조건
- 유니크·세트 장비의 개별 효과 (`InitializeEquipmentEffect` 안의 아이템별 분기 수십 개)
- NPC 이벤트 중 상점·은행·의사·거래소 외의 종류(퀘스트, 게시판, 메일 등), 은행에 맡길 수 없는 물건 구분, 의사·은행 NPC가 가끔 주는 심부름 퀘스트, 수량이 한정된 상점 물건의 재고 저장, 군단 상점 세금
- 기술, 원거리 공격의 총알, 방패와 무기를 함께 쓰는 양손 장비(부위 100), 명성, PK 벌칙, 그룹 경험치
- 새 캐릭터의 시작 위치 (계정 DB 쪽 값. 지금은 부활 위치와 같은 맵 21로 둠)

### 시험할 때

원작 수치 그대로라 1레벨(체력 50, 공격력 7~10)로는 맵 1의 몬스터(첩자 체력 146, 공격력 36)를 잡기 어렵습니다.
채팅창에 `/레벨 60` 을 치거나 `START_LEVEL=60 npm start` (윈도우: `set START_LEVEL=60 && npm start`) 로 레벨을 올려 시험할 수 있습니다.
받은 점수는 화면 오른쪽 아래 능력치 창의 + 단추로 분배합니다.

## 저장과 비밀번호

캐릭터는 이름마다 `save/이름.json` 파일 하나에 저장됩니다(레벨, 능력치, 소지품, 장비, 돈, 은행, 위치). 나갈 때와 1분마다 저장하고,
같은 이름으로 다시 들어오면 이어서 합니다. 처음 쓰는 이름이면 그때 넣은 비밀번호로 캐릭터가 만들어지고, 다음부터는 그 비밀번호가 맞아야 들어옵니다.
파일에는 비밀번호 자체가 아니라 소금값과 scrypt 해시만 들어갑니다.

원작은 로그인 서버와 DB로 계정을 관리하고 계정 하나에 캐릭터가 여럿입니다. 여기서는 이름 하나가 곧 캐릭터 하나입니다.
새 이름으로 들어올 때 접속 화면에서 아홉 직업 중 하나를 고릅니다. 직업에 따라 겉모습, 능력치 1점당 오르는 양, 체력 회복량, 착용 가능한 장비가 달라집니다(모두 서버 실행 파일의 값).

새 캐릭터의 처음 상태는 원작 로그인 서버(`svIP.exe`의 `CIPClient::ProcessNewCharacterID`, 3.944와 4.5 모두 같음)가 DB에 넣는 값 그대로입니다.

| 항목 | 값 |
|---|---|
| 레벨·능력치 | 레벨 1, 근력·정신력·민첩성·기골 각 10, 보너스 점수 2 |
| 체력·마력·기력 | 50 · 50 · 0 |
| 돈 | 300 |
| 소지품 | 붕어빵 5개, 주택가1 지도, 주택가2 지도, 주택가3 지도 |
| 직업별 기술 | [기술, 특수 기술] = 필라르 1·91, 아즐라 11·101, 사다드 21·111, 데스티노 31·121, 박진희 41·131, 캐논 51·141, 한지화 71·161, 루나레나 61·151, 라비타 81·171 (기술 자체는 아직 미구현, 번호만 저장) |
| 시작 위치 | 처음 접속할 때 고름: 초보존(맵 68의 6, 45) 또는 주택가2 병원(맵 22의 8, 14) (`CIPClient::ProcessPacket` 0x4016b6) |
