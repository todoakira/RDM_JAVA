## 이번에 고친 것
- **상점·교환소 첫 메뉴:**
  - 원작은 상점 NPC 와 말하면 먼저 작은 메뉴가 뜬다.
    - 상점은 iw-bs-ba 의 BUY·SELL·Cancel 이다.
    - 교환소는 iw-bt-ba 의 BUY·SELL·REPAY·Cancel 이다.
  - 고른 뒤에 큰 창이 열린다.
  - 메뉴 줄을 누르는 자리는 그림에서 잰 값이다.
- **교환소에 올리기:**
  - 브라우저 입력 상자 대신 원작 iw-bu-ba 창을 쓴다 (물건 이름·그림, Buyer, Price, OK·Cancel).
  - **Buyer 칸 = 지정 구매자:** 이름을 적으면 그 사람만 살 수 있고, 비우면 누구나 살 수 있다.
    - 근거 1: Message 0/0/175 "Enter Buyer's name. or leave blank for anyone to buy."
    - 근거 2: tblExchange 에 Buyer 칸이 있다.
    - 근거 3: ProcessExchangeBuyItem 0x40f7bd 는 Buyer 가 비어 있지 않고 내 이름과 다르면 시스템 글 0x61 "Only the selected buyer can buy that item." 을 보낸다.
    - 전에 쓰던 '남길 말' 은 없앴다.
  - 수량은 원작 메시지 창(입력칸)으로 묻는다 (0/0/170 "Quantity:").
- **쓰러졌을 때:**
  - 원작은 창 없이 시스템 글을 보이고, 화면을 누르면 다시 선다. 우리 판이 만든 "쓰러졌습니다 / 다시 시작" 창은 없앴다.
    - 사람에게 졌으면 Message 0/2/9 "Player %s killed you. Click to respawn." 이다.
    - 그 밖에는 0/2/10 이다.
- **머리 위 이름:** "이름 Lv.N" → 이름만 보인다.
  - 원작 클라이언트에서 레벨을 붙이는 글 형식을 찾지 못했다. 원작 "Level : %d" 는 캐릭터 고르기 화면에만 쓰인다.
- **캐릭터 고르기 이름 칸:** 원작 형식 "%s\nLevel : %d" (0x10018a62) 다.
- **게시판 창:**
  - 원작 일반 창 바탕 iw-ge-ba (500×400) 를 쓰고, 원작 기본 위치 (150,80) 에 둔다.
  - 원작 게시판은 게임 안 웹 창이었다. 이 바탕을 썼는지는 확인하지 못했다.
- **조작 안내·위치 글:** 원작에 없어서 기본으로 숨겼다. F12 로 켠다.

- **화면 대화 줄** (Main.dll 0x10010d2f 그리기, 0x1001c080 줄 넣기, 0x1001be90 종류 거르기):

## 아직 원작과 다르거나 확인 못 한 것
- **브라우저 입력 상자:** 모두 원작 메시지 창(iw-me-ba + 입력칸)으로 바꿨다.
  - 은행 금액은 0/0/45·0/0/69 로 묻는다.
  - 캐릭터 지우기는 원작이 생년월일을 받는다 (0/0/51). 우리 계정에는 생년월일이 없어서 비밀번호를 받는다 (0/0/10).
- **군단 창들:** 군단 정보 창 말고는 원작 위치를 모른다 (가운데).
- **접속 화면:**
  - 머리·옷 색 고르기, Prolog·Credits, Change User Info 가 아직이다.
  - 로그인 창 세로 자리는 짐작이다.
- **몸 그리기 효과:** PK 벌칙 등 (모드 0x620) 의 색. Dfx_p5s.dll 을 풀어야 한다.
- **글꼴:** 화면 전체를 굴림 쪽 글꼴(Gulim·GulimChe·굴림·돋움, 없으면 맑은 고딕) 12px 로 바꿨다. 굴림이 없는 컴퓨터에서는 대신 쓰는 글꼴로 보인다.
  - 원작 근거: 도움말 창 글꼴 높이 −12, 대화 줄 글꼴 높이 −12·굵기 400.

## 걸음 시간 (원작 클라이언트에서 확인)
우리 판은 서버가 걸음 시간을 정한다. 원작 서버는 걸음 시간을 재지 않고 클라이언트가 정한다. 그래서 클라이언트에서 값을 옮겼다.
- **한 걸음 거리:**
  - 대각선 (±24, ±12) 픽셀, 세로 (0, ±24), 가로 (±48, 0).
  - 근거: 0x10030be0 의 방향별 목표.
- **장마다 움직임:** 장마다 속도만큼 옮긴다. 남은 거리가 속도 이하면 목표에 붙는다 (0x10031574).
- **속도 s:** 걷기 1, 달리기 2 (0x1003244c, 0x10032492).
- **장마다 픽셀 (0x10030d60):** 장 수 = 축마다 ⌈거리 / 속도⌉ 중 큰 쪽.

  | 상태 | 대각선 | 가로·세로 | 걷기 (대각·세로·가로) | 달리기 |
  |---|---|---|---|---|
  | 보통 | (4s, 2s) | (6s, 3s) | 6·8·8 (처음 값이 맞았다) | 3·4·4 |
  | 빠름 (+0x20) | (8s, 4s) | (12s, 6s) | 3·4·4 | 2·2·2 |
  | 중간 (+0x38) | (6s, 3s) | (8s, 4s) | 4·6·6 | 2·3·3 |
  | 느림 (+0x24) | (2s, s) | (3s, ⌊3s/2⌋) | 12·24·16 | 6·8·8 |

- **고르는 차례:**
  1. 중간이고 느림이 아니면 중간.
  2. 빠름이 아니고 느림이면 느림.
  3. 빠름이고 느림이 아니면 빠름.
  4. 그 밖은 보통.
- **상태가 켜지는 조건:** 클라이언트가 받는 정보 구조의 비트로 정한다 (0x10031ce0~0x10031d99).
  - 빠름: 효과 3 (+0x1a & 8), 효과 36 (+0x1e & 0x10).
    - 효과 36 은 이노큘레이터 스피드가 켠다 (서버 +0x4028 & 0x10).
  - 빠름: 효과 63 WindWalker.
    - rm3944cl NewWalkerEffect 0x100021ae 가 정보 +0x10 & 0x10 을 본다.
    - 서버 rm3944 NewSendUseSkill 0x100023df 가 이 비트에 효과 63 을 넣는다. 효과 63 칸은 0x10002174 에서 확인했다.
  - 중간: WindWalker 가 아니고 정보 +0x20 & 0x20 (효과 53).
  - 느림: 효과 14 (+0x1b & 0x40), 효과 43 (+0x1f & 8), 효과 55 (+0x20 & 0x80).

## 이노큘레이터 아이콘 줄 (Main.dll 0x1003c6b0 만들기, 0x1003c9d0 받기, 0x1003ccf0·0x1003ce10 그리기)
- 화면 (8,529) 에 494×35 판을 둔다 (0x10010e63).
- 패킷 0xf9 (종류 13 개의 2비트 상태)를 받으면 줄을 고친다.
  - 0 이 아니게 된 종류는 줄 끝에 더한다.
  - 0 이 된 종류는 줄에서 뺀다.
  - 상태 1·2 가 하나라도 있으면 깜빡임을 켠다 (+0x3c).
- 아이콘은 si-01-ma ~ si-13-ma (35×35) 이다. 이름은 0x100c55e8~ 에 있다.
- 자리: 켜진 차례대로 x = 0, 38, 76, … y 0 이다 (0x1003c5e2 표).
- 깜빡임 (장 수 +0x40 은 50ms 마다 하나):
  - 상태 1: 장 수 & 7 ≥ 4 이면 반투명.
  - 상태 2: 장 수 % 20 ≥ 10 이면 반투명.
- 깜빡일 때 그리는 법 (반투명이 아니었다):
  - Main 은 CopyTo 에 효과 구조를 넘긴다. 깃발 +0 = 0x800, +0x18 = 0x50, +0x1c~+0x2c = 0 (0x1003cd99~0x1003cdbd).
  - ExStage 는 화면 픽셀 형식을 보고 Dfx 깃발을 정한다 (0x100098d1~0x10009900).
    - 555 이면 1, 565 이면 2. 빨강 마스크 < 파랑 마스크면 0x82.
  - Dfx_p6s.dll 의 모드 0x800 (0x10010cae → 0x100108d0) 은 구조 +0x18~+0x2c 를 색 비율(%)로 쓴다.
    - 원본 색 3 개와 바탕 색 3 개에 각각 비율을 곱해 더한다.
    - 깃발에 0x80 이 없으면 +0x18 은 빨강, +0x1c 는 초록, +0x20 은 파랑이다.
  - 바탕 비율 +0x24~+0x2c 가 모두 0 이면 바탕을 보지 않는다 (0x10011310). 원본 색에 비율만 곱해 덮어쓴다.
  - 그래서 565 RGB 화면에서는 빨강 × 80/100, 초록·파랑 0 이 된다. 아이콘이 어두운 빨강으로 바뀐다.
  - 우리 판도 그렇게 그린다. 5비트 빨강 r5 → ⌊r5 × 80/100⌋ 이다.
