# 움직이는 오브젝트 (Main.dll 분석)

## 원작이 하는 일
- 오브젝트 정의 파일(DATAs/Obj/objNNNNN.rmd) 머리의 이름 뒤 두 값은 **움직임 장 수**와 **한 장에 든 칸 수**다.
  - 예: obj00030 = 8장, 19칸.
  - 파일 끝의 움직임 표(pump)는 CSpriteManager::GetPump 로 읽는다.
- 맵을 그릴 때 (0x100363e0), 칸마다 오브젝트 파일의 정보(가상함수 +0x40)를 보고 장 수가 1 이 아니면 그림을 바꾼다:
  - 그릴 칸 = 놓인 칸 번호 + 한 장 칸 수 × 표[(길이 − 화면장 수 % 길이) % 길이]
  - Staff.dll CtPump::Get: 위치가 길이 이상이면 0 으로 돌린 뒤 표 값을 준다. 그래서 표는 **거꾸로** 읽힌다.
- 화면장 수(0x100c6bc0)는 맵을 한 번 그릴 때마다 1 씩 오른다 (0x10036784). 화면 한 장은 50ms 다 (README 의 주 반복문 항목).
- 표 길이는 CtPump::Init 에서 1바이트로 넘어가므로 255 를 넘으면 잘린다. 지금 자료에서 가장 긴 표는 236 이라 해당이 없다.
- 오브젝트 파일 1483개 가운데 248개에 표가 있다. 바닥 타일(Tle)에는 표가 없다.

## 우리 판
- **변환 (tools/convert.js):** 움직이는 오브젝트는 장마다 겹 목록을 만들어 맵 JSON 의 objAnims/animObjs 에 넣는다.
  - 154장 맵에 9만9천여 개가 놓여 있다.
- **화면 (public/client.js):** 그릴 때 장을 골라 그 장의 겹만 그린다.

## 아직 안 한 것
- 맵 0x47(71) 의 파일 0x185 는 맵 상태값(+0xac, 1~4)과 칸 위치에 따라 0x184 로 바뀐다. 어떤 상태인지 확인하지 못해 빼 두었다.
